# Security Static Site Audit

## What I do
- Audit CI/CD supply chain for unpinned tools, broken cache keys, missing checksums
- Scan for web security gaps (CSP, SRI, X-Frame-Options, frame-ancestors)
- Detect information leakage (API keys, secrets, emails, PIX keys, build metadata)
- Review configuration hardening (.gitignore, HTTPS, HSTS, robots.txt)
- Identify content injection & stored XSS vectors (raw HTML fragments, search JS)
- Audit third-party comment systems (Giscus config, crossorigin, iframe isolation)

## When to use me
- Static site generated by any SSG (Marmite, Hugo, Jekyll, Zola, 11ty, Pelican)
- Deployed to GitHub Pages, GitLab Pages, Cloudflare Pages, Netlify
- Uses Giscus, utterances, or other GitHub-based comment systems
- Has CI/CD pipeline with `cargo install`, `npm install`, or similar
- Loads external CDN resources (Giscus, highlight.js, Fuse.js, Google Fonts)
- Custom markdown headers/footers that inject raw HTML
- Search functionality loading index as JSON

## Guidelines

### 1. CI/CD Supply Chain Audit

Analyze `.github/workflows/*.yaml` (or equivalents):

**Unpinned tool installations:**
- Check `cargo install <tool>` — MUST use `--version <x.y.z>`
- Check `npm install -g <tool>` — MUST use `@<version>` or `npm ci` with lockfile
- Verify `hashFiles()` cache keys reference files that actually exist in the repo
- Verify `actions/checkout` `fetch-depth` is appropriate (2 is sufficient for diff checks)

**Pass criteria:**
- All `cargo install` / `npm install` commands pin exact versions
- Cache keys reference existing files (`Cargo.lock`, `package-lock.json`)
- No secret leakage in workflow YAML (no hardcoded tokens, no `echo ${{ secrets.* }}`)
- Actions use commit SHAs or verified publishers, not just major version tags

### 2. Web Security Audit

**Content Security Policy (CSP):**
- Check for `<meta http-equiv="Content-Security-Policy">` in generated HTML
- If present, verify it allows only required origins:
  - `script-src 'self' https://giscus.app https://cdnjs.cloudflare.com`
  - `style-src 'self' 'unsafe-inline' https://cdnjs.cloudflare.com`
  - `frame-src https://giscus.app`
  - `frame-ancestors 'none'`
  - `img-src 'self' https:`
- If absent, flag as MEDIUM severity

**Clickjacking protection:**
- Check for CSP `frame-ancestors` directive
- Note: GitHub Pages adds `X-Frame-Options: DENY` server-side automatically

**Referrer-Policy:**
- Check for `<meta name="referrer" content="...">` or `Referrer-Policy` HTTP header
- Recommended: `strict-origin-when-cross-origin` (default in modern browsers, but explicit is better)
- If absent, flag as LOW — browsers leak `Referer` on cross-origin requests

**Permissions-Policy:**
- Check for `<meta http-equiv="Permissions-Policy" content="...">` or HTTP header
- Recommended minimum: `camera=(), microphone=(), geolocation=()`
- If absent, flag as INFO — no sensitive APIs on static sites, but defense-in-depth

**Mixed Content:**
- Scan generated HTML for `src="http://` or `href="http://` on HTTPS pages
- GitHub Pages enforces HTTPS, but user-added content may have hardcoded HTTP links
- Run: `rg 'src="http://' site/*.html` — flag as HIGH if any match

**Subresource Integrity (SRI):**
- Find all `<script src="https://...">` and `<link href="https://...">` in generated HTML
- Each external resource MUST have `integrity="sha384-..."` attribute
- Generate hashes: `curl -sL <URL> | openssl dgst -sha384 -binary | openssl base64 -A`
- ESM dynamic imports (e.g., Fuse.js from CDN) cannot use SRI — flag to vendor locally

**robots.txt:**
- Verify it does not expose sensitive paths (admin, config, backup files)
- Blog/static sites typically want full crawling: `Allow: /`

**search_index.json leakage:**
- If search is enabled, verify `html` field only contains published content
- Flag if full page body text is exposed as JSON (acceptable for blogs, document the trade-off)

### 3. Information Leakage Scan

Run high-signal regex patterns across the entire repo (excluding generated output):

```bash
# API keys and tokens
rg -n 'sk-[a-zA-Z0-9]{20,}' --type-add 'web:*.{html,js,json}'  # OpenAI
rg -n 'ghp_[a-zA-Z0-9]{36}'                                      # GitHub PAT
rg -n 'gho_[a-zA-Z0-9]{36}'                                      # GitHub OAuth
rg -n 'ghu_[a-zA-Z0-9]{36}'                                      # GitHub user token
rg -n 'AKIA[0-9A-Z]{16}'                                         # AWS Access Key
rg -n '-----BEGIN (RSA |EC |OPENSSH |PGP )?PRIVATE KEY-----'    # Private keys
rg -n 'xox[abprs]-[0-9]{10,}'                                    # Slack tokens
rg -n 'AIza[0-9A-Za-z_-]{35}'                                    # Google API key
rg -n 'ant-[a-zA-Z0-9]{24,}'                                     # Anthropic
rg -n 'pk\.'                                                      # Stripe publishable
rg -n 'sk\_live\_'                                                # Stripe secret
```

**Information exposure review:**
- Check for published email addresses in content — verify they are intentionally public
- Check for PIX/venmo/payment keys in content — verify placeholder vs real
- Check `marmite.json` or build metadata for system info leakage (absolute paths, hostname, env vars)
- Check git history for accidentally committed secrets: `git log --diff-filter=A --name-only`

### 3.1 Git History Secret Scan

Scan the full git history for accidentally committed secrets:

```bash
# Scan all commits with gitleaks (preferred)
gitleaks detect --source . --report-path gitleaks-report.json --verbose 2>/dev/null

# Manual scan with rg across all tracked files in history
git log --all --diff-filter=A --name-only --pretty=format: | sort -u | xargs -I{} sh -c 'git log --all --format="%H %s" -- "{}" | head -1 && echo "  File: {}"'

# Check for specific patterns in git history
git log --all -p | rg -n 'sk-[a-zA-Z0-9]{20,}|ghp_[a-zA-Z0-9]{36}|AKIA[0-9A-Z]{16}|-----BEGIN.*PRIVATE KEY-----'
```

- Flag any matches as CRITICAL — secrets in history require rotation + BFG repo-cleaner
- If no matches, PASS with INFO note

### 3.2 Branch Protection Audit

Check repository settings for branch protection on `main`:
```bash
# GitHub CLI check
gh api repos/{owner}/{repo}/branches/main/protection 2>/dev/null
```

Verify:
- Pull request required before merge
- Required approvals (≥1)
- Dismiss stale reviews
- Require status checks (CI passing)
- No direct pushes to `main`
- Require signed commits (optional, defense-in-depth)

If not visible via CLI, flag as INFO — manual verification in GitHub UI required.

### 3.3 `.well-known/security.txt` Check

Verify presence of RFC 9116 security.txt at `/.well-known/security.txt`:
- MUST exist at site root or `/.well-known/` directory
- MUST contain at minimum: `Contact:` field
- SHOULD include: `Preferred-Languages:`, `Canonical:`, `Expires:`

If absent, flag as LOW — recommended for responsible disclosure.

### 4. Configuration Hardening

**.gitignore review:**
- MUST contain patterns to prevent accidental secret commits:
  ```
  *.env
  .env.*
  .DS_Store
  Thumbs.db
  *.pem
  *.key
  *.p12
  node_modules/
  ```
- If `.gitignore` is empty, flag as MEDIUM severity

**HTTPS verification:**
- Verify `url` in config uses `https://` (not `http://`)
- Note HSTS status (GitHub Pages does not support custom headers; suggest Cloudflare if needed)

**Build output tracking:**
- If `site/` or equivalent build output is tracked in git, verify AGENTS.md matches actual git status
- Flag if documentation claims `site/` is committed but it is actually untracked (or vice-versa)

**Custom JS/CSS review:**
- Verify custom.js and custom.css are safe (no obfuscated code, no inline event handlers)
- Flag empty stubs as informational — they become injection vectors when modified

### 5. Content Injection & Stored XSS

**Raw HTML injection points:**
- Check `content/_markdown_header.md` and `content/_markdown_footer.md` — these inject raw HTML into every page
- Verify they contain only safe content (HTML comments, benign markup)
- Flag as LOW severity stored XSS vector if editable by untrusted users

**Search JS escaping:**
- Verify search.js uses `innerText` or `textContent` (NOT `innerHTML`) when inserting user-facing results
- Verify error messages do not render raw API responses

**Markdown rendering:**
- Check that markdown code blocks use `<pre><code>` wrapper, not raw HTML passthrough
- Verify Marmite/Hugo/Jekyll markdown parser properly escapes HTML in code blocks

### 6. Third-Party Comments (Giscus)

**Giscus configuration audit:**
- Verify `data-repo` and `data-repo-id` match the correct repository
- Verify `data-category` and `data-category-id` are set to appropriate GitHub Discussions category
- Verify `crossorigin="anonymous"` is present (prevents credential leakage)
- Verify `async` attribute (non-blocking load)
- Verify `data-mapping="pathname"` for URL-based comment association
- Check `data-theme="preferred_color_scheme"` or explicit theme (dark mode safety)

**Security notes:**
- Giscus loads comments from GitHub Discussions API into an isolated iframe
- No server-side component — injection risk is limited to GitHub's markdown sanitization
- Repo IDs and category IDs are intentionally public identifiers
- Verify the repo allows Discussions for the configured category

### 7. Reporting

For each finding, document:
- **Severity**: CRITICAL / HIGH / MEDIUM / LOW / INFO
- **File**: exact file path with line number
- **Evidence**: quoted text or command output
- **Impact**: what an attacker could do
- **Fix**: concrete remediation steps

Produce a summary table with PASS/FAIL counts per axis.

## Examples

### Example: Full audit of Marmite blog

1. Read `.github/workflows/main.yaml` → find `cargo install marmite` without `--version` → **FAIL (HIGH)**
2. Check `hashFiles('**/Cargo.lock')` → no Cargo.lock in repo → **FAIL (MEDIUM)**
3. Read `site/about.html` → search for CSP meta tag → not found → **FAIL (MEDIUM)**
4. Check Giscus script in `content/_comments.md` → verify `crossorigin`, `async`, `data-repo-id`
5. Scan repo for secrets: `rg 'sk-[A-Za-z0-9]'` → no matches → **PASS**
6. Check `.gitignore` → empty file → **FAIL (MEDIUM)**
7. Verify `search.js` uses `innerText` → safe → **PASS**
8. Check `_markdown_header.md` → HTML comment only → **PASS (INFO)**

### Example: Detecting exposed PIX key

```bash
rg -n '[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}' content/*.md
```

If matches found, verify they are placeholders (e.g., `xxx`) or intended public keys.
